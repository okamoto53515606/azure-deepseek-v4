# 【検証用】DeepSeek-V4.1-Flash を Azure AI Foundry にデプロイして curl で確認する

- 作成日: 2026-09-28
- 検証済み: 2026-09-28 / `eastus` / `GlobalStandard` / `--sku-capacity 20`

作業の最後に、この資料で作った Azure のリソースは**リソースグループごと削除**する。削除手順は最後にまとめる。

---

## Azure AI Foundry で動かす（DeepSeek-V4.1-Flash）

DeepSeek 自社 API だけでなく、Microsoft Azure の **Azure AI Foundry（Microsoft Foundry）** 経由でも DeepSeek 系モデルをデプロイできます。
ここでは Azure が「Direct from Azure」として販売している `DeepSeek-V4.1-Flash` を、**Azure CLI でデプロイして curl で疎通確認するまで**の手順を示します。

ℹ️ **`DeepSeek-V4.1-Flash` の位置づけ**:
**Causal Encoder-Decoder 構成（552B パラメータ・prefill 8B / decode 16B 活性）**、**最大 100 万トークンのコンテキスト**、**画像入力**、**1〜100 の連続的な reasoning effort** を備えたマルチモーダル MoE モデルです。
**Azure AI Foundry では Preview モデルとして提供されています**（2026-09-28 時点、`eastus`）。
Azure 側の仕様は Microsoft Learn と Microsoft Foundry ブログの記載に基づきます。コマンド列は **2026-09-28 に `eastus` で動作確認済み**のものです。

### 前提

- Azure サブスクリプション（リソースを作成できる権限があること。リソースプロバイダー登録には **Owner** 権限が必要です）
- Azure CLI（`az`）。`az cognitiveservices` 系コマンドは core に同梱されているため、Azure CLI 2.60 以降であれば追加拡張は不要です
- `az login` で対象サブスクリプションにログイン済みであること

### 使うプレースホルダ

| プレースホルダ | 意味・指定する値 |
|---|---|
| `<SUBSCRIPTION_ID_OR_NAME>` | 使う Azure サブスクリプションの ID または名前 |
| `<RESOURCE_GROUP>` | リソースグループ名（例: `rg-deepseek`） |
| `<LOCATION>` | リージョン（例: `eastus`）。`DeepSeek-V4.1-Flash` は `eastus` で確認済み。モデルによって提供リージョンが異なるため、Azure ポータルのモデルカタログで確認してください |
| `<ACCOUNT_NAME>` | Azure AI Services アカウント名。**全世界で一意**にする必要があります（例: `dsv41flash0928`）。`--custom-domain` にも同じ値を使います |
| `<DEPLOYMENT_NAME>` | デプロイ名（任意）。**API 呼び出しの `model` に指定するのはモデル名ではなく、このデプロイ名です**（例: `deepseek-v4-1-flash`） |
| `<MODEL_VERSION>` | モデルのバージョン文字列。**実値は STEP 3 の `az cognitiveservices account list-models` で確認してください**（2026-09-28 時点の実値は `2026-09-10`） |
| `<API_KEY>` | Azure AI Services アカウントのキー（手順内で CLI から取得します） |

### STEP 0 — Azure CLI の準備とリソースプロバイダー登録

最初にこれを済ませておくと、後の手順で `MissingSubscriptionRegistration` エラーに当たりません。

```
# Azure CLI のバージョン確認（2.60 以降を推奨）
az version

# 未ログインならログイン
az login

# 使うサブスクリプションを選択
az account set --subscription "<SUBSCRIPTION_ID_OR_NAME>"

# リソースプロバイダーを登録（MissingSubscriptionRegistration 対策）
az provider register --namespace Microsoft.CognitiveServices

# 登録状態を確認（Registered になるまで数分かかることがあります）
az provider show --namespace Microsoft.CognitiveServices --query registrationState -o tsv
```

### STEP 1 — リソースグループを作成

```
az group create \
  --name "<RESOURCE_GROUP>" \
  --location "<LOCATION>"
```

### STEP 2 — Azure AI Services アカウントを作成

`--custom-domain` を指定すると、以降のエンドポイントが `https://<ACCOUNT_NAME>.openai.azure.com/` の形式になります。

```
az cognitiveservices account create \
  --name "<ACCOUNT_NAME>" \
  --resource-group "<RESOURCE_GROUP>" \
  --kind AIServices \
  --sku S0 \
  --location "<LOCATION>" \
  --custom-domain "<ACCOUNT_NAME>" \
  --assign-identity \
  --allow-project-management true \
  --yes
```

💡 `--assign-identity` と `--allow-project-management` は、Foundry プロジェクトで Entra ID 認証やプロジェクト管理を使う場合のオプションです。**API キーで curl するだけなら省略できます**（付けたままでも動作します）。

### STEP 3 — DeepSeek-V4.1-Flash をデプロイ

まず利用可能なモデルとバージョンを確認し、その値でデプロイします。

```
# デプロイ可能な DeepSeek 系モデルとバージョンを確認
az cognitiveservices account list-models \
  -n "<ACCOUNT_NAME>" -g "<RESOURCE_GROUP>" \
  --query "[?contains(name,'DeepSeek')].{name:name,format:format,version:version,lifecycle:lifecycleStatus}" -o table
```

2026-09-28 時点の実測値は次のとおりです（作業当日に再確認してください）。

```
Name                 Version     Format    Lifecycle
-------------------  ----------  --------  ---------
DeepSeek-V4.1-Flash  2026-09-10  DeepSeek  Preview
```

ℹ️ **`--model-version` は必ず実値を確認する**: 上の表に出た `version` をそのまま使います。`DeepSeek-V4.1-Flash` は Preview のため、予告なく新しいバージョンが追加されます。

⚠️ **`--query` の結果が空になる場合**: `az cognitiveservices account list-models` の戻りは**フラット構造**で、`name` / `version` / `format` が最上位にあります。一方 `az cognitiveservices model list --location` の戻りは `model` でネストされます。両者を混同しないでください。

続けてデプロイします。SKU は `GlobalStandard`、`--sku-capacity` の値は下の注意書きを参照してください。

```
az cognitiveservices account deployment create \
  --name "<ACCOUNT_NAME>" \
  --resource-group "<RESOURCE_GROUP>" \
  --deployment-name "<DEPLOYMENT_NAME>" \
  --model-name "DeepSeek-V4.1-Flash" \
  --model-version "<MODEL_VERSION>" \
  --model-format "DeepSeek" \
  --sku-name "GlobalStandard" \
  --sku-capacity 20
```

💡 `--sku-capacity` はクォータ（Requests Per Minute と Tokens Per Minute、千トークン単位）として消費されます。実測では **`--sku-capacity 1` = 1 リクエスト / 60 秒 + 1,000 トークン / 60 秒**、つまり **`20` で 20 RPM / 20,000 TPM** でした。容量が足りないと `InsufficientQuota` でデプロイに失敗することがあるため、その場合は値を調整するか、Azure ポータルでクォータの増加を申請してください。

## ⚠️ `--sku-capacity` の実運用（実測・2026-09-28）

- `--sku-capacity 1` でも**デプロイ自体は成功します**が、**少なすぎて API を少し使っただけでクォータ不足のエラー**になります。実運用では `20` 以上を推奨します。
- 確保する容量は `az cognitiveservices usage list` で確認できる **limit（上限）の範囲内**で指定してください。
- **カタログの `maxCapacity` は目安にしないでください。** 実測では `DeepSeek-V4.1-Flash` のカタログ表記が `1,000,000` であるのに対し、**サブスクリプションの `limit` は `20`** でした。実際に割り当てできるのは `limit` までです。
- 実測値（`eastus`）: `AIServices.GlobalStandard.DeepSeek-V4.1-Flash  current=0.0 limit=20.0` → **capacity 20 が最大**。
- **上限まで使い切らないでください。** 使い切ると、同じサブスクリプション・同じリージョンで同モデルのデプロイをもう 1 本作れなくなります。20 を超えたい場合は、先に Azure ポータルでクォータの増加を申請してください。
- TPM は**「プロンプト + `max_tokens`」**で消費されます。`max_tokens` を大きく取ると、実際の出力が短くてもその分を消費します。

```
# 現在のクォータ使用量と上限を確認（LOCATION はデプロイ先リージョン）
az cognitiveservices usage list --location "<LOCATION>" -o table
```

## ⚠️ デプロイを変更したいとき

- **`deployment update` というサブコマンドはありません。** capacity を変更したい場合も、**同じデプロイ名で `deployment create` を再実行**します。
- デプロイ名は後から変更できません。変えたい場合は別名で作り直し、アプリ側の `model` を差し替えます。
- アカウント名は世界で一意です。作成時に名前の衝突エラーが出たら、`<ACCOUNT_NAME>` を変えて STEP 2 からやり直します。

### STEP 4 — 接続情報を環境変数に入れる

```
# エンドポイント（OpenAI 互換）と API キーを取得
export AZURE_AI_ENDPOINT="https://<ACCOUNT_NAME>.openai.azure.com/openai/v1/"
export AZURE_AI_API_KEY="$(az cognitiveservices account keys list \
  --name "<ACCOUNT_NAME>" \
  --resource-group "<RESOURCE_GROUP>" \
  --query key1 -o tsv)"

# API 呼び出しの model に入れるのはデプロイ名
export DEPLOYMENT_NAME="<DEPLOYMENT_NAME>"

echo "endpoint=$AZURE_AI_ENDPOINT"
test -n "$AZURE_AI_API_KEY" && echo "api_key=set"
```

**成功の目印:** `endpoint=https://....openai.azure.com/openai/v1/` と `api_key=set` が表示されます。

💡 `az cognitiveservices account keys list` の戻りは `key1` / `key2` の 2 つです。どちらでも同じように使えます。

### STEP 5 — curl で疎通確認

```
curl -sS --http1.1 "$AZURE_AI_ENDPOINT/chat/completions" \
  -H "Content-Type: application/json" \
  -H "api-key: $AZURE_AI_API_KEY" \
  -X POST \
  -d '{
    "model": "'"$DEPLOYMENT_NAME"'",
    "messages": [
      { "role": "user", "content": "Reply with just OK." }
    ]
  }'
```

✅ 応答 JSON が返れば疎通完了です。`model` にデプロイ名を渡している点に注意してください（モデル名 `DeepSeek-V4.1-Flash` を渡すと 404 などになることがあります）。
環境変数にキーを置きたくない場合は `-H "api-key: <API_KEY>"` を直接指定します。
Entra ID（旧 Azure AD）で認証する場合は、公式チュートリアルにあるとおり `DefaultAzureCredential` 等でスコープ `https://ai.azure.com/.default` のトークンを取得する方式も使えます。

**応答例（実測）**

```json
{
  "id": "43cc521c21684ab9889fd9c00d4e61fa",
  "model": "deepseek-v4-1-flash",
  "choices": [
    { "index": 0, "message": { "role": "assistant", "content": "OK" }, "finish_reason": "stop" }
  ],
  "usage": { "prompt_tokens": 9, "completion_tokens": 2, "total_tokens": 11 }
}
```

💡 `--http1.1` はこの環境（WSL2）で必要な指定です。付けないと `curl` の HTTP/2 が応答なしでハングします（Python / httpx は HTTP/1.1 なので影響しません）。

### STEP 6 — レート制限が意図どおりか確認する

`-D` でヘッダを保存すると、`--sku-capacity` が反映されているか確認できます。

```
# STEP 5 の curl に -D /tmp/h.txt を足して実行してから、ヘッダを確認する
grep -i -E '^HTTP|x-ratelimit' /tmp/h.txt
```

**成功の目印（capacity 20 の実測）:**

```
HTTP/1.1 200 OK
x-ratelimit-key: deepseek-v4-1-flash
x-ratelimit-limit-requests: 20
x-ratelimit-limit-tokens: 20000
x-ratelimit-renewalperiod-requests: 60
x-ratelimit-renewalperiod-tokens: 60
```

`limit-requests` / `limit-tokens` が `--sku-capacity` に比例していれば、デプロイは意図どおりです。

## ⚠️ `MissingSubscriptionRegistration` が出たら

次のようなエラーです（HTTP 409 / Conflict）。**サブスクリプションで `Microsoft.CognitiveServices` リソースプロバイダーが未登録**なだけなので、リソース作成側の問題ではありません。

```
MissingSubscriptionRegistration
The subscription is not registered to use namespace 'Microsoft.CognitiveServices'.
```

- **対処1（CLI）**: `az provider register --namespace Microsoft.CognitiveServices` を実行し、`az provider show --namespace Microsoft.CognitiveServices --query registrationState -o tsv` が `Registered` になるまで待ちます（数分かかることがあります）。
- **対処2（ポータル）**: Azure ポータル →「サブスクリプション」→「リソースプロバイダー」→ `Microsoft.CognitiveServices` を選び「登録」。
- **権限**: 登録には**サブスクリプションの Owner 権限**が必要です。権限が無い場合は管理者に依頼してください。
- 公式のトラブルシューティング: [Register a resource provider](https://learn.microsoft.com/en-us/azure/azure-resource-manager/troubleshooting/error-register-resource-provider)

## ⚠️ その他のエラー

| エラー | 最初に確認するもの |
|---|---|
| `404` / `Not Found` | `model` に**モデル名**を渡していないか（渡すのは**デプロイ名**）。`AZURE_AI_ENDPOINT` の綴りも確認する |
| `401` / `Unauthorized` | `AZURE_AI_API_KEY` が空、または別アカウントのキー |
| `429` | 利用上限。`x-ratelimit-remaining-*` と `retry-after` を確認し、`--sku-capacity` を見直す |
| `400` | モデル名、モデル形式、SKU、リクエスト形式 |
| `InsufficientQuota` | `az cognitiveservices usage list` の `limit`。`--sku-capacity` を下げるか、クォータ増加を申請する |
| 応答が返らずハングする | WSL 環境では `curl --http1.1` を付ける |
| 接続・証明書エラー | 会社プロキシ、CA 証明書、DNS |

## DeepSeek 公式 API と Azure 経由の違い

対象は中国公式（`api.deepseek.com`）と、Azure 直ホストの `DeepSeek-V4.1-Flash`（version `2026-09-10`、`GlobalStandard`、Preview）。Azure 側の所見は 2026-09-28 時点の実測です。

| 区分 | 観点 | 中国公式 | Azure 直ホスト |
|---|---|---|---|
| API | Chat Completions | あり | あり（capabilities に `chatCompletion`） |
| API | Anthropic 互換 | `https://api.deepseek.com/anthropic` | 使えない。`/anthropic/v1/messages` は `api_not_supported`。ブログも触れていない |
| API | Responses API | あり。使うならこちら | **使うべきでない。** 宣言されているのは Chat Completions。カタログに `responses` 印は無く、ブログも触れていない。経路自体は HTTP 200 だったが、対応の宣言ではない |
| API | Tool / JSON / Vision | あり | カタログ上、画像入力あり。Tool / JSON は Chat Completions の範囲 |
| API | 思考の制御（Chat Completions） | 既定は思考オン、既定の強さは `high`。オンオフは `thinking.type`、強さは `reasoning_effort` の `low` / `high` / `max` [6] | `thinking` パラメータは指定できない。送ると 400。オンオフと強さは `reasoning_effort` だけ。`none` は思考なし、`low` は思考あり |
| API | コンテキスト / 最大出力 | 1M / 384K | カタログはコンテキスト 1M、出力上限 128K |
| 料金 | 入力 cache miss | 0.30（ピーク） / 0.15（オフピーク） | 0.30 |
| 料金 | 入力 cache hit | 0.006（ピーク） / 0.003（オフピーク） | 0.006 |
| 料金 | 出力 | 1.20（ピーク） / 0.60（オフピーク） | 1.20 |
| 料金 | オフピーク半額 | あり（平日 UTC 01:00–04:00 と 06:00–10:00、中国祝日を除く） | **なし** |
| 容量 | 上限の意味 | 同時接続。`deepseek-flash` はアカウントあたり 2,500。超過は 429 | SKU capacity。1 capacity ≒ 1 リクエスト / 分 + 1,000 トークン / 分。カタログ上限は 1,000,000 |
| 容量 | いまの実効値 | 契約次第。増枠申請は追加料金なし、と公式は書く | サブスクリプションのクォータ次第（**検証環境の実測は 20** = 20 リクエスト / 分 + 20,000 トークン / 分） |
| データ | 推論後に残すか | 残し得る。入力はアカウントがある限り保持し得る [1]。ディスクキャッシュは既定で、未使用なら通常数時間〜数日で削除 [3] | 使うのは Chat Completions。モデル自体は残さない [4]。乱用監視でフラグされたプロンプトは、人の確認用に保存され得る。Preview は監視の扱いが異なり得る [4] |
| データ | 人が中身を見るか | 「人は見ない」とは書いていない。不正調査、規約違反、法令対応でアクセス・共有し得る [1] | 自動レビューは保存しない。人が見るのは、フラグされたものか乱用パターンに限る。見るのは認可された Microsoft 社員 [4][5]。Modified abuse monitoring の申請が通ると、その保存と人の確認は止まる |
| データ | 学習に使うか | モデル訓練・技術改善に使うと書き、オプトアウト権はある。API 入力が自動で訓練対象外とは書いていない [1] | 基礎モデルの訓練には使わない。DeepSeek 社にも渡さない [4] |
| データ | 処理する国 | DeepSeek のインフラ。国外移転は「必要なら保護措置」とだけ [1] | そのモデルがある任意の Azure リージョン。日本にも中国にも閉じない。リソースは East US [4] |
| データ | 保存する国 | 中国。準拠法は中国本土、管轄は杭州 [1][2] | 乱用監視の保存先は、リソースの geography（米国）[4] |
| データ | 日本閉じ | 不可 | 不可。V4.1 に Data Zone / 単一リージョン SKU は無い |
| データ | 中国公式へ渡るか | そのものが中国公式 | 渡さない [4] |

料金の単位は USD / 100 万トークン。

[1] は、ポリシー自身が「オープンプラットフォームで開発者が作った下流アプリのエンドユーザー個人情報は、このポリシーの対象外」と書いている。公式 API のプロンプト保持を、チャットアプリと同じ条項だけで断定はできない。

## ⚠️ capacity の数字は環境で変わる

- 上の「容量」行は**カタログと契約の話**で、実際にデプロイできる値は**サブスクリプションのクォータ次第**です。
- 本資料の検証環境では `AIServices.GlobalStandard.DeepSeek-V4.1-Flash` の `limit` が **20** だったため、STEP 3 でも `--sku-capacity 20` としています。
- クォータ上限が 10,000 の環境であれば capacity 10,000（= 10,000 リクエスト / 分、10,000,000 トークン / 分）まで取れます。ただし**これは別環境の例**で、本資料の検証環境の値ではありません。
- **中国公式の「2,500 同時接続」と Azure の「capacity」は単位が違います。横並びの数字として比較しないでください。**

### 要点

- 中国公式はオフピークが半額で、出力 384K と Responses / Anthropic がある。代わりにデータは中国に置かれ、推論後に残さない保証も「訓練に使わない」も契約上ない。
- Azure 直は、DeepSeek 社に渡さず Azure 請求にできる。料金は公式ピークと同じ。日本閉じではなく、Preview で、乱用監視の人的確認が既定であり得る。出力上限はカタログ上 128K。
- Azure 直は Chat Completions を使う。Responses はカタログもブログも対応を宣言しておらず、使うべきでない。思考は `reasoning_effort`。
