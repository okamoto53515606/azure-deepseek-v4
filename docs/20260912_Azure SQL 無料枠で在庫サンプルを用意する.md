# 【検証用】Azure SQL 無料枠で在庫サンプルを用意する

- 対象: 第2部（README）の第4章（SQL Server）を、自社の DB を用意せずに試したい人
- 用途: 社内 PoC（動作検証）。本番導入手順ではない
- 作成日: 2026-09-12

この資料は、[第2部: データ連携と活用（README）](../README.md)の第4章を試すための**検証用データベース**を用意する手順。Azure SQL Database の無料枠を使い、在庫のサンプルデータを投入する。

作業の最後に、この資料で作った Azure のリソースは**リソースグループごと削除**する。削除手順はこの資料の最後にまとめる。

## 0. 作るもの

| 種類 | 名前（例） | 内容 |
|---|---|---|
| リソースグループ | `rg-dsv4-sqlpoc` | 後片付けを 1 コマンドにするための入れ物 |
| SQL サーバー | `dsv4-sqlpoc-<ランダム>` | `japaneast`。管理ログインは `sqlpocadmin` |
| データベース | `inventory_poc` | **無料枠**（`GP_S_Gen5` / Serverless / 32GB / 上限超過時は自動一時停止） |
| ファイアウォール | 自分の IP のみ | 全開放しない |
| 表 | `dbo.Inventory` | 在庫の元データ（12 商品） |
| ビュー | `dbo.InventoryOrderView` | 予測在庫・推奨発注量・優先度・アラート理由を計算 |
| 読み取り専用ユーザー | `dsv4_readonly` | 上のビューへの `SELECT` だけ |

**無料枠の注意**

- 1 サブスクリプションにつき 1 データベース。上限はおおむね 32GB・月 100,000 vCore 秒。
- 上限を超えたときの動作は `AutoPause`（課金せず一時停止）にする。`BillOverUsage` は選ばない。
- リージョンによっては新規 SQL サーバーを受付けていない。2026-09-12 時点では `eastus` が作成不可で、`japaneast` で作成できた。
- 料金と条件は変わる。作業当日に [Azure SQL Database の無料枠](https://learn.microsoft.com/azure/azure-sql/database/free-offer) を確認する。

## 1. 前提を確認する

| 確認内容 | 完了の目印 |
|---|---|
| 第2部 0 章の `.env` | `grep -c . .env` が 5 以上 |
| 第2部 0 章の `uv add` | `pyproject.toml` の `dependencies` が 5 件 |
| Azure CLI | `az account show` が表示される |
| Toolbox | `toolbox --version` が表示される（第2部 3.3） |

`Microsoft.Sql` のリソースプロバイダーが未登録だと、サーバー作成が `MissingSubscriptionRegistration` で失敗する。先に登録する。

```bash
az provider register --namespace Microsoft.Sql --wait
```

## 2. 値を決めて `.env` に追記する

サーバー名は世界で一意にする必要がある。パスワードはこの場で生成し、`.env` にだけ書く（画面には表示しない）。

```bash
export SQL_RG="rg-dsv4-sqlpoc"
export SQL_LOCATION="japaneast"
export SQL_SERVER="dsv4-sqlpoc-$(python3 -c 'import secrets;print(secrets.token_hex(3))')"
export MSSQL_DATABASE="inventory_poc"
export MSSQL_ADMIN_USER="sqlpocadmin"
export MSSQL_ADMIN_PASSWORD="$(python3 -c 'import secrets,string; a=string.ascii_letters+string.digits; print("".join(secrets.choice(a) for _ in range(24))+"#7a")')"
export MSSQL_USER="dsv4_readonly"
export MSSQL_PASSWORD="$(python3 -c 'import secrets,string; a=string.ascii_letters+string.digits; print("".join(secrets.choice(a) for _ in range(24))+"#9b")')"

cat >> .env <<EOF

# SQL Server（検証用 Azure SQL。後片付けで削除する）
MSSQL_HOST="${SQL_SERVER}.database.windows.net"
MSSQL_PORT="1433"
MSSQL_DATABASE="${MSSQL_DATABASE}"
MSSQL_USER="${MSSQL_USER}"
MSSQL_PASSWORD="${MSSQL_PASSWORD}"
MSSQL_ADMIN_USER="${MSSQL_ADMIN_USER}"
MSSQL_ADMIN_PASSWORD="${MSSQL_ADMIN_PASSWORD}"
SQL_RG="${SQL_RG}"
SQL_SERVER="${SQL_SERVER}"
SQL_LOCATION="${SQL_LOCATION}"
EOF

chmod 600 .env
grep -c . .env   # 行数が増えたことを確認する（値は表示しない）
```

`MSSQL_USER` / `MSSQL_PASSWORD` は**第4章で使う読み取り専用ユーザー**、`MSSQL_ADMIN_*` は**セットアップ専用の管理ユーザー**。`.env` は Git に登録されず、後片付けで削除する。

## 3. SQL サーバーを作る

```bash
az group create -n "$SQL_RG" -l "$SQL_LOCATION" -o none

az sql server create \
  -g "$SQL_RG" -n "$SQL_SERVER" -l "$SQL_LOCATION" \
  -u "$MSSQL_ADMIN_USER" -p "$MSSQL_ADMIN_PASSWORD" -o none

MYIP="$(curl -s --max-time 10 https://api.ipify.org)"
az sql server firewall-rule create \
  -g "$SQL_RG" -s "$SQL_SERVER" -n "client-poc" \
  --start-ip-address "$MYIP" --end-ip-address "$MYIP" -o none

echo "[OK] ${SQL_SERVER}.database.windows.net（許可 IP: ${MYIP}）"
```

**成功の目印:** `[OK] <サーバー名>.database.windows.net（許可 IP: ...）` が表示される。

`Location '...' is not accepting creation of new Windows Azure SQL Database servers` と出た場合は、`SQL_LOCATION` を `westus3` などに変えてやり直す。**このときサーバー名も新しくする**（失敗した作成は元のリージョンに名前だけ残ることがあり、同名では別リージョンに作れない）。

## 4. 無料枠のデータベースを作る

```bash
az sql db create \
  -g "$SQL_RG" -s "$SQL_SERVER" -n "$MSSQL_DATABASE" \
  -e GeneralPurpose -f Gen5 -c 2 --compute-model Serverless \
  --use-free-limit --free-limit-exhaustion-behavior AutoPause \
  --backup-storage-redundancy Local -o none

az sql db show -g "$SQL_RG" -s "$SQL_SERVER" -n "$MSSQL_DATABASE" \
  --query "{status:status,useFreeLimit:properties.useFreeLimit,exhaustion:properties.freeLimitExhaustionBehavior}" -o json
```

**成功の目印:** `"status": "Online"` と `"useFreeLimit": true`、`"exhaustion": "AutoPause"` が表示される。

## 5. 在庫サンプルを投入する

リポジトリの `samples/seed_inventory_sqlserver.py` が、表・ビュー・読み取り専用ユーザーを作る。`pymssql` はこのスクリプト専用の追加ライブラリなので、`--with` で渡す。

```bash
uv run --env-file .env --with pymssql python samples/seed_inventory_sqlserver.py
```

**成功の目印:** `inserted: 12 rows` に続いて、商品の一覧が表示される。

```text

created: dbo.Inventory / dbo.InventoryOrderView
inserted: 12 rows
created: read-only user dsv4_readonly (SELECT on dbo.InventoryOrderView only)
```

## 7. 作成されるデータ

### 7.1 表 `dbo.Inventory`（在庫の元データ）

| 列 | 内容 |
|---|---|
| `ProductCode` / `ProductName` | 商品コード / 商品名 |
| `AvailableStock` | 販売可能在庫 |
| `AvgDailySales` | 1 日あたりの平均販売数（実績から計算済み） |
| `InboundQty` / `InboundDate` | 発注済み数量と入荷予定日（未定は NULL） |
| `SafetyStockDays` / `LeadTimeDays` / `OrderLot` | 安全在庫日数 / 調達リードタイム / 発注ロット |
| `DataAsOf` | データ基準日 |

### 7.2 ビュー `dbo.InventoryOrderView`（判定結果）

予測式と丸めはビュー側で計算する。DeepSeek には計算させない。

| 列 | 計算内容 |
|---|---|
| `PredictedStockAtArrival` | 入荷時点の予測在庫。`在庫 + 入荷予定 - 平均販売数 × (入荷までの日数 + 安全在庫日数)` |
| `RecommendedOrderQty` | 予測在庫が負のとき、`OrderLot` 単位で切り上げた数量。それ以外は 0 |
| `Priority` | 1 = 緊急、2 = 要確認、3 = 通常 |
| `AlertReason` | 入荷予定日が未定 / 入荷時点で在庫が不足 / 販売実績が不足 / 安全在庫を下回る見込み / 発注の必要はありません |

12 商品の内訳は、緊急 4 件（`SKU-1001`・`SKU-1003`・`SKU-1005`・`SKU-1010`）、要確認 3 件、通常 5 件。第4章のプロンプトで「推奨発注量が 0 より大きい商品」を指定すると、この緊急 4 件が対象になる。

## 8. 後片付け

```bash
set -a; . ./.env; set +a
az group delete -n "$SQL_RG" --yes --no-wait
echo "[OK] リソースグループ ${SQL_RG} を削除中（SQL サーバー・DB・FW ルールが消える）"
```

続けて `.env` から SQL Server の行を削除する。第2部 7.4 の `rm -f .env` でも構わない。

```bash
python3 - <<'PY'
from pathlib import Path

drop = ("MSSQL_", "SQL_RG", "SQL_SERVER", "SQL_LOCATION", "# SQL Server")
path = Path(".env")
kept = [l for l in path.read_text(encoding="utf-8").splitlines() if not l.startswith(drop)]
path.write_text("\n".join([l for l in kept if l.strip()]) + "\n", encoding="utf-8")
print("[OK] .env から SQL Server の設定を削除しました")
PY
chmod 600 .env
```

無料枠は、データベースを削除するとサブスクリプションの枠が戻る。`--no-wait` を付けたので削除はバックグラウンドで進む。確認する場合:

```bash
az group list --query "[?name=='rg-dsv4-sqlpoc'].name" -o tsv
```

**注意:** この資料で作るのは検証用の Azure SQL だけ。第2部で使う Azure AI（DeepSeek）のリソースは別のリソースグループにあるため、このコマンドでは消えない。そちらは第2部 7.3 で削除する。
